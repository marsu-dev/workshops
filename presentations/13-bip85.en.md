# BIP-85: one seed for many secrets

unscheduled

Deterministically derive independent seeds and secrets from a single BIP32 root.

---

## Objectives

- Understand the problem solved by BIP-85
- Read a BIP-85 derivation path
- Identify its main applications
- Prepare reliable backup and recovery procedures
- Know the risks before using it

---

## The problem

Each wallet or application may require its own secret:

- BIP39 mnemonic
- BIP32 extended key
- WIF key for Bitcoin Core
- password or other entropy

Reusing one mnemonic everywhere increases exposure. Backing up many mnemonics becomes difficult.

---

## The BIP-85 idea

A BIP32 root acts as an **entropy root**.

Compatible software can recreate many distinct secrets from it. The same path and parameters always produce the same result.

BIP-85 is an informational application standard; it replaces neither BIP32 nor BIP39.

---

## Deterministic, not freshly random

```text
master root + application + parameters + index
                         ↓
               same derived secret
```

- Changing the index produces another secret
- Restoring the master root lets you regenerate everything
- Derived secrets must not be confused with the root

---

## Cryptographic process

1. Derive a private key through a **fully hardened** path
2. Compute:

```text
HMAC-SHA512(key="bip-entropy-from-k", msg=k)
```

3. Obtain 512 bits of entropy
4. Truncate or encode it for the application

The HMAC transformation separates the produced entropy from the derived private key.

---

## Namespace

The BIP-85 prefix is:

```text
m/83696968'/application'/.../index'
```

`83696968` represents the four ASCII bytes for `BIP` followed by `0x85`.

Every level is hardened, shown by the apostrophe `'`.

---

## Example: BIP39 mnemonic

Path format:

```text
m/83696968'/39'/language'/words'/index'
```

First 12-word English mnemonic:

```text
m/83696968'/39'/0'/12'/0'
```

Use index `1'` for the next one. A 12-word mnemonic uses 128 bits of entropy; 24 words use 256 bits.

---

## Standardized applications

- `2'`: HD-Seed WIF for Bitcoin Core
- `32'`: XPRV extended key
- `39'`: BIP39 mnemonic
- `128169'`: hexadecimal bytes
- `707764'` / `707785'`: Base64 / Base85 passwords
- `828365'`: RSA keys through BIP85-DRNG
- `89101'`: dice, PINs and custom alphabets
- `128002'`: Nostr keys

---

## What the COLDCARD Q can derive

Under `Advanced/Tools > Derive Seeds (BIP-85)`, the COLDCARD Q offers:

- 12-, 18- or 24-word BIP39 mnemonics
- a WIF private key
- a BIP32 root XPRV
- 32- or 64-byte hexadecimal entropy
- deterministic passwords

Other applications defined by BIP-85 are not necessarily available in this menu.

---

## BIP39 derivation on COLDCARD Q

For 12 English words at index `0'`:

```text
m/83696968'/39'/0'/12'/0'
```

The Q lets you choose **12, 18 or 24 words**, followed by an index. The output can be imported into another wallet or temporarily activated on the COLDCARD.

Each word-count + index combination produces a different mnemonic.

---

## WIF and XPRV derivations

**WIF — one private key**, usable notably as Bitcoin Core's HD seed:

```text
m/83696968'/2'/0'
```

**XPRV — a complete new BIP32 root**:

```text
m/83696968'/32'/0'
```

The COLDCARD Q can temporarily activate a derived XPRV, whereas a WIF remains one private key and is not a BIP39 mnemonic.

---

## Hexadecimal entropy

The Q can export raw bytes for a compatible application:

```text
32 bytes: m/83696968'/128169'/32'/0'
64 bytes: m/83696968'/128169'/64'/0'
```

- 32 bytes = 256 bits
- 64 bytes = 512 bits
- hexadecimal form alone does not specify how an application must use the entropy

Do not import these values into software that does not precisely document its expected format.

---

## BIP-85 passwords

The COLDCARD Q uses the **PWD BASE64** application with a fixed length of 21 characters:

```text
m/83696968'/707764'/21'/0'
```

- approximately 126 bits of entropy
- up to 10,000 default indexes, from 0 to 9999
- display, QR, NFC or USB keyboard emulation

Keyboard emulation must target a **QWERTY** layout; AZERTY or QWERTZ can type different characters.

---

## Procedure on the COLDCARD Q

1. Unlock the COLDCARD Q
2. Open `Advanced/Tools > Derive Seeds (BIP-85)`
3. Read the warning and select the format
4. Enter and record the index
5. Verify the path and value on screen
6. Import the output into the target wallet or application
7. Test recovery before putting the secret into real use

The 9999 limit can be removed under `Danger Zone > B85 Idx Values > Unlimited`.

---

## Exporting from the Q

Depending on the format, the value can be:

- saved to **MicroSD A** or **MicroSD B**
- saved to Virtual Disk
- sent over **NFC**
- displayed as a **QR** code
- typed through USB keyboard emulation
- temporarily activated with `0` for BIP32/BIP39

These exports contain the secret in cleartext. Minimize copies, delete temporary files and verify the environment before any transfer.

---

## Q recovery context

If a BIP39 passphrase was active on the COLDCARD Q during derivation, recovery requires **that exact passphrase** in addition to the root, format and index.

A passphrase later added in the child wallet is separate: BIP-85 regenerates the child mnemonic, not that additional passphrase.

Also record the parent wallet fingerprint so you can confirm that the correct root is active.

---

## Practical organization

Example allocation:

```text
index 0' → everyday wallet
index 1' → savings wallet
index 2' → Lightning node
index 3' → test environment
```

The labels are your documentation; BIP-85 does not remember the purpose assigned to an index.

---

## What to back up

- The master root, protected to the highest standard
- Any optional passphrase
- Application, parameters and index for every derivation
- Compatible software or implementation
- A tested recovery procedure

Without the exact path, finding a secret may become a lengthy or practically impossible search.

---

## Security model

**Benefit:** exposing one child secret does not directly reveal the root or its siblings.

**Main risk:** exposing the master root compromises every derived secret, past and future.

The central backup therefore becomes a critical concentration point.

---

## Good practices

- Derive secrets on an offline or compatible hardware device
- Never enter the master root into a web tool
- Assign one unique, documented index per use
- Verify paths on the device screen
- Test recovery before depositing funds
- Keep highly exposed secrets separate if your threat model requires it

---

## Limits and compatibility

- Not every wallet supports BIP-85
- The standard depends on a BIP32 root, regardless of how it was created
- BIP-85 is not backward-compatible with other derivation schemes
- A different path, language or word count changes the result
- Deterministic generation does not make secrets publicly linkable

---

## Recovery checklist

1. Restore the correct BIP32 root
2. Select the same application
3. Reuse the exact language, length and index
4. Derive offline
5. Compare a known public address
6. Never test by exposing the root to a third-party service

---

## Key takeaways

- **One root backup**, many application secrets
- Reproducible outputs through hardened paths
- Easier backup makes protection of the root more important
- Paths and indexes are part of the operational backup
- BIP-85 is powerful only with a documented and tested procedure
